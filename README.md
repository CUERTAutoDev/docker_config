# docker_config

Docker configurations and scripts used to set up a local ROS 2 + simulator environment.

## System architecture

This repository is used to spin up a **two-container simulation stack** with Docker Compose:

- **`ros2_humble_env`**: a ROS 2 Humble development container (based on `osrf/ros:humble-desktop`) where your workspace is mounted and development happens.
- **`carla_sim`**: a CARLA 0.9.16 simulator container that can run with display forwarding or in headless mode.

Both services use host networking and IPC to simplify ROS 2 communication and simulator integration.

## Migration direction: Gazebo Classic -> CARLA

We are standardizing on:

- **ROS 2 Humble** as the robotics middleware baseline.
- **CARLA** as the main simulator for autonomous driving workflows.

Gazebo Classic is being phased out for this setup, and CARLA is the primary simulation runtime in the Compose stack generated by the setup script.

## Setup script walkthrough

The setup script configures and optionally starts the full environment.

### 1) Detect host user identity

The script reads your host user details:

- UID/GID via `id -u` and `id -g`
- username via `id -un`

These are used to create a matching user inside the ROS container so mounted files keep correct ownership.

### 2) Prompt for ROS container and workspace paths

You are asked for:

- ROS container name (default: `ros2_humble_sim`)
- host workspace path (default: `/home/$USER/ros2_ws`)
- container workspace path (default: `/workspace`)

The script creates the host workspace and `~/.ssh` directory if missing.

### 3) Prompt for CARLA mode

You choose whether CARLA runs headless:

- `y` -> adds `-RenderOffScreen`
- `n` (default) -> enables X11 display forwarding

### 4) Prompt for GPU passthrough

You choose whether GPU passthrough is enabled (default: `y`).
If enabled, choose vendor:

- `nvidia` (default)
- `intel`
- `amd`

### 5) Generate `Dockerfile`

The script writes a ROS 2 Humble-based Dockerfile that:

- installs base networking/dev utilities and `ros-humble-rmw-fastrtps-cpp`
- creates a non-root user matching host UID/GID
- installs `carla==0.9.16` Python API
- auto-sources ROS 2 in `/etc/bash.bashrc`
- sets working directory to your selected container workspace

### 6) Generate `compose.yml`

The script writes a Compose file with two services:

- **`ros2_humble_env`**
  - builds from local Dockerfile
  - mounts X11 socket, `/dev`, SSH directory, and workspace
  - sets ROS-related environment variables (`ROS_DOMAIN_ID`, `RMW_IMPLEMENTATION`)
  - applies optional GPU configuration

- **`carla_sim`**
  - uses image `carlasim/carla:0.9.16`
  - runs `--ros2` and optional `-RenderOffScreen`
  - enables X11 mounts for non-headless mode
  - applies optional GPU configuration

### 7) Add shell alias for quick container access

The script appends an alias to `~/.bashrc`:

- alias name: `enter_<container_name>`
- alias command: `docker exec -it <container_name> bash`

Example default alias: `enter_ros2_humble_sim`

### 8) Optionally build and start now

If you accept the final prompt, it runs:

```bash
xhost +local:root
docker compose up -d --build
```

After startup, open a **new terminal** and use the alias to enter the ROS container.

## Typical usage after setup

```bash
docker compose up -d --build
# then in a new terminal
enter_ros2_humble_sim
```

> If your container name differs from the default, use the alias generated by the script.

## Local installation alternative (without Docker)

If you need a comparable host-native setup, use the official installation guides:

- ROS 2 Humble docs: https://docs.ros.org/en/humble/Installation.html
- CARLA docs (build/binary + Python API): https://carla.readthedocs.io/

Use those guides to install ROS 2 Humble, CARLA 0.9.16, and the CARLA Python API locally while keeping middleware and simulator versions aligned with this repository's containerized stack.
